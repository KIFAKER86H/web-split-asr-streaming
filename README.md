# NECTEC Live Transcribe — Split Display

รุ่นที่แยกจอ **ถอดเสียง** กับ **แปลภาษา** ออกจากกันคนละแท็บ/หน้าต่าง แต่ยังใช้ pipeline เดิม
(ถอดเสียง → แปล แสดงผลโดยไม่ต้องรอกัน) และหน้าตา/แอนิเมชัน/แผงตั้งค่าคงเดิมทั้งหมดจาก
[`../web`](../web) — ต่างกันแค่ **แต่ละแท็บแสดงได้ทีละภาษา** และตัวกลางส่งข้อมูลเปลี่ยนจาก
React state ในหน้าเดียว มาเป็น **`SharedWorker` hub** ตัวเดียวที่ทุกแท็บของ origin นี้ต่อเข้าไปใช้ร่วมกัน

สร้างด้วย **Next.js 16 (App Router) + React 19 + Tailwind CSS v4**
ตัวถอดเสียงใช้ **AssemblyAI Universal-Streaming v3** ผ่าน WebSocket

## แนวคิด

หน้าเว็บมีแค่เส้นทางเดียว (`/`) — **สิ่งที่แท็บนั้นแสดง (ถอดเสียง/แปล) ไม่ใช่ route**
แต่เป็นค่าที่อยู่ใน `sessionStorage` ของแท็บนั้นเอง (หรือกำหนดผ่าน `?mode=transcribe` /
`?mode=translate` ตอนเปิดครั้งแรก) ปรับได้จากแผงตั้งค่า (<kbd>F2</kbd>) แถวบนสุด
เพราะงั้นเปิด URL เดียวกันในสองแท็บ (หรือสอง OBS browser source) แล้วตั้งแท็บหนึ่งเป็น
"ถอดเสียง" อีกแท็บเป็น "แปลภาษา" ได้เลย — ดู `src/lib/tab-mode.ts`

ทุกแท็บที่เปิดจาก origin เดียวกันแชร์ **`SharedWorker` เดียว**
(`public/workers/caption-hub.js`) ซึ่งเป็นเจ้าของ:

- การเชื่อมต่อ WebSocket ไปหา AssemblyAI (เชื่อมครั้งเดียวไม่ว่าจะเปิดกี่แท็บ)
- คิวการแปลภาษา (เรียก `/api/translate` ครั้งเดียวต่อประโยค ไม่ซ้ำ ไม่ว่าจะมีแท็บแปลกี่แท็บ)
- ทรานสคริปต์และคำแปลที่สะสมไว้ — แท็บที่เพิ่งเปิดใหม่ได้ของเดิมทันทีจาก hub

ส่วนไมโครโฟน (`getUserMedia`, `AudioWorklet`) ต้องอยู่ในแท็บ (SharedWorker ไม่มี DOM/media
API) — แท็บไหนกด <kbd>F4</kbd> ก่อนจะกลายเป็น "producer" จับเสียงแล้วส่ง PCM ขึ้น hub
แท็บอื่นกด <kbd>F4</kbd> เพื่อ "หยุด" ได้เหมือนกันแม้ไม่ใช่ตัว producer

ดูรายละเอียดโปรโตคอลทั้งหมดที่ `src/lib/hub-protocol.ts` (ฝั่ง type) และ
`public/workers/caption-hub.js` (ตัว worker เอง — ทำไมต้องเขียนเป็น JS ธรรมดา
และทำไมต้องมี heartbeat แทนการพึ่ง "port ปิด" ซึ่งทั้ง Firefox และ Chrome ไม่ส่งอีเวนต์นี้ให้)

## สลับชุด API (ถอดเสียง + แปล) แบบไม่มีรอยต่อ

`.env` อธิบายชุด API ได้สองชุด — ชุดปกติ กับชุดที่สอง (ตัวแปรลงท้าย `_B`) ที่ตั้งใจไว้เป็น
คนละ endpoint/บัญชี/ภูมิภาคก็ได้ กด <kbd>F3</kbd> (เปลี่ยนได้จากแผง F2 → หัวข้อ "ชุด API") เพื่อสลับ
ทั้งถอดเสียงและแปลไปใช้อีกชุดหนึ่งพร้อมกันทันที:

- **ยังไม่เริ่มอัด** — แค่จำไว้ว่ารอบต่อไปจะต่อชุดไหน ไม่มีการเปิดการเชื่อมต่อใด ๆ ก่อน
- **กำลังอัดอยู่** — hub เปิดการเชื่อมต่อไปชุดใหม่คู่ขนานกับของเดิม รอจนต่อสำเร็จ
  แล้วค่อยสลับ PCM ที่กำลังไหลเข้ามาให้ไปทางชุดใหม่ (make-before-break) เสียงจึงไม่มีช่วงที่
  ไม่ถูกส่งไปไหนเลยแม้แต่เสี้ยววินาที ส่วนชุดเก่าไม่ได้ถูกตัดทิ้งทันที แต่ปล่อยให้ปิดตัวเองแบบ
  เงียบ ๆ เผื่อเซิร์ฟเวอร์ยังมีประโยคค้างจะส่งกลับมา
- **ถ้าไม่ได้ตั้งชุดที่สองไว้** (`ASSEMBLYAI_WS_ENDPOINT_B` ว่าง) ทั้งคีย์ลัดและปุ่มในแผง
  ตั้งค่าจะไม่ทำอะไรเลย — แผงตั้งค่าเองก็จะไม่โชว์หัวข้อนี้ให้กดผิดด้วย

ดูกลไกเต็ม ๆ ที่คอมเมนต์เหนือ `handleSwapSlot` ใน `public/workers/caption-hub.js`

## เริ่มใช้งาน

ต้องมี Node.js 20.9+

```bash
cp .env.example .env     # แล้วแก้ ASSEMBLYAI_WS_ENDPOINT
npm install
npm run dev              # http://localhost:3000 (หรือใช้ -p เลี่ยงพอร์ตชนกับ ../web)
```

เปิดสองแท็บ (หรือมากกว่า) ไปที่ URL เดียวกัน — ตั้งแท็บหนึ่งเป็นถอดเสียง อีกแท็บเป็นแปลภาษา
จากแผง F2 ของแต่ละแท็บ แล้วกด F4 จากแท็บไหนก็ได้เพื่อเริ่ม/หยุด

ขึ้น production:

```bash
npm run build
npm start
```

## รันด้วย Docker

```bash
cp .env.example .env     # แล้วแก้ค่าให้ตรงของจริง
docker compose up --build
```

เปิด `http://localhost:3000` ได้เลย — image รัน `next start` ตัวเดียวกับที่ `npm start`
รันนอก Docker (**ไม่ได้ใช้** `output: "standalone"` ของ Next.js เพราะโหมดนั้นเปลี่ยนคำสั่ง
เริ่มเป็น `node .next/standalone/server.js` แทน ซึ่งจะทำให้ `npm start` ธรรมดาใช้ไม่ได้อีกต่อไป
— ดูคอมเมนต์ใน `next.config.ts`) ปิด image optimization ไว้ด้วย `images.unoptimized`
เพราะรูปในแอปมีแค่โลโก้ที่ไซซ์นิ่งอยู่แล้ว ไม่ต้องมีใครมา resize ระหว่างรัน และเลี่ยงปัญหา
`sharp` บน Alpine ไปในตัว

**`.env` ไม่เคยถูกก็อปปี้เข้าไปใน image** — ทุกค่าอ่านจาก `process.env` ตอน request
จริง ไม่ใช่ตอน build (ดูคอมเมนต์ใน `src/lib/server/config.ts`) `docker-compose.yml`
ส่งให้ผ่าน `env_file:` เท่านั้น เปลี่ยนค่าใน `.env` แล้ว `docker compose restart` พอ
ไม่ต้อง build ใหม่

**ข้อควรระวังเรื่องเครือข่าย:** `ASSEMBLYAI_WS_ENDPOINT` เป็นสายที่ **เบราว์เซอร์ของผู้ใช้ปลายทางต่อตรง** (ไม่ใช่ container) — container ต้องมองเห็นแค่ `ASSEMBLYAI_TOKEN_ENDPOINT` (ออก token) กับ `TEXT_BASE_URL` (แปลภาษา) เท่านั้น ถ้า endpoint พวกนี้อยู่หลัง VPN/network ภายใน ต้องดูให้ทั้งเครื่อง Docker host และเครื่องผู้ใช้ (สำหรับ WS) เข้าถึงได้ตามที่แต่ละอันต้องการ

ไม่รันแบบ compose ก็ได้ ใช้ `docker build -t nectec-split . && docker run -p 3000:3000 --env-file .env nectec-split` ได้เหมือนกัน

## ต่างจาก `../web` ตรงไหน

| เรื่อง | `../web` (จอเดียว) | แอปนี้ (แยกจอ) |
| --- | --- | --- |
| การแสดงผล | ถอดเสียง+แปล บนจอเดียว แบ่งด้วย `CAPTION_SPLIT_RATIO` | ทีละภาษาต่อแท็บ เลือกจาก F2 |
| ตัวกลางส่งข้อมูล | React state ในหน้าเดียว | `SharedWorker` hub ใช้ร่วมกันทุกแท็บ |
| WebSocket ไป AssemblyAI | เปิดจากหน้าเว็บโดยตรง | เปิดจาก hub (worker) |
| การแปลภาษา | เรียกจากหน้าเว็บ ทีละประโยค | เรียกจาก hub ครั้งเดียวต่อประโยค กระจายผลให้ทุกแท็บ |
| ไมโครโฟน | เปิดจากหน้าเว็บ | เปิดจากแท็บที่กด F4 ก่อน ("producer") ส่ง PCM ขึ้น hub |

ค่า `.env` ทั้งหมด (`ASSEMBLYAI_*`, `TEXT_*`, `CAPTION_*`) ความหมายเหมือนเดิมทุกตัว
ยกเว้น **ไม่มี `CAPTION_SPLIT_RATIO`** เพราะแต่ละแท็บแสดงภาษาเดียวเสมอ และมีตัวแปรชุดใหม่
ลงท้าย `_B` เพิ่มเข้ามาสำหรับฟีเจอร์สลับชุด API (ด้านบน) — ดู `.env.example`

## ข้อจำกัด

`SharedWorker` ไม่มีใน Safari (ทั้ง macOS และ iOS) — เปิดด้วย Safari จะขึ้นข้อความแจ้งเตือน
บนจอแทน ใช้ Chrome หรือ Firefox แทนสำหรับตอนนี้
